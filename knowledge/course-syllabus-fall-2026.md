Course Description
This course offers an introduction to the principles of mobile interface design and application
development. It covers the fundamentals of programming, user interfaces, gestures, feedback,
and data storage. Students will move through the complete mobile application development
pipeline from Swift, SwiftUI, Xcode, building to devices, and finally App Store submission. This
class emphasizes experimentation, prototyping, iteration, and rapid development.
Learning Objectives
• Develop mobile apps using Swift and Xcode
• Design effective UI for mobile and tablet screens
• Learn the fundamentals of multi-paradigm programming
• Understand the hardware and software constraints of developing for mobile platforms
• Experience the mobile development pipeline from start to finish, prototyping to release
• Submit a polished app to the Appstore
Prerequisites
Some programming experience.
Course Structure
The course is for a letter grade. The class will be a mix of technical demonstrations, software
workshop exercises, lectures, as well as collective critique sessions. Lectures cover technology,
design, interface, and development. Technical demonstrations may be recorded and shared with
the students afterward for further review. Recordings, announcements and additional resources
will be posted to Discord. Students are expected to participate in lecture, discussions and
critiques. Students are responsible for completing assignments and projects by stated
deadlines. Please familiarize yourself with Brightspace and Discord before the course begins.

Description and Assessment of Assignments
The following is a breakdown of the expectations for assignments and other assessable tasks.
Unless otherwise noted, all submissions will be due 1 hour prior to class on Brightspace.
Exercises
The course will begin with a series of one-week exercises that explore swift and Xcode as a
platform for app development and device experimentation. The exercises build on each other
both in concept and technical expectations. The focus here will be on creativity and discovery.
Each exercise will be submitted to Brightspace as a .zip of the entire project folder,
accompanied by a paragraph description.
Exercise 1 - Hello World
Create a simple Hello World app. Start with with the Swift example template and create a text
message that will display on the user’s screen when the app runs. Change as many things as
you possibly can to differentiate it from the default “Hello World” template. This is your
opportunity to get really creative with the design elements of SwiftUI. Once this is complete, test
run the app in the Xcode device simulator.

## Page 4

Exercise 2 - Clicker Game
Using what you know about variables, functions, structs, conditionals and other programming
fundamentals, create a simple clicker game. The app should display a counter of how many
times the user has clicked the icon on the screen. The user should also be presented with
awards after certain click achievements have been met.
Exercise 3 - UI and UX
Create button and screen based navigation. Imagine the type of app you would like to build and
create a title screen, a login page, and an onboarding flow. The screens will be navigated
through using buttons, input fields, and swipe gestures. Design your own sprites for some of the
buttons and backgrounds. Test run the app in the Xcode device simulator. If that is successful,
attempt to build it to your iPhone.
Exercise 4 - Touches and Gestures
Design an app that takes advantage of touch states rather than traditional button based UI.
Consider the affordances of touch duration, gestures, and multiple touches at once. Present the
user with an interface that necessitates this experience and offers an intuitive, easy to use
benefit over other types of UX.
Exercise 5 - Sound and Haptics
Create an application that incorporates sound and haptic feedback. This can be a new creation
or a polish pass on previous exercise. The submission should include a title screen, sound
effects, haptic feedback, and music. Create original sprite assets as needed. You may use
either original or free use audio assets. Make sure the build runs well on your phone.
Midterm Project - Data Sets (group)
Working in groups of 4, develop an app that utilizes an internal or external dataset. This set
could be data collected manually, created by users, or an external database. Display the data in
a meaningful way. Design the user interactions with intentionality. Consider the type of actions
the user would want or need to do with this particular type of data.
The midterm is a polished project, developed over a 3 week sprint, with milestones along the
way. The focus here will be on rapid development and iterative design. The midterm will be
submitted via a GitHub repo, accompanied by a paragraph description. Every student in a group
project must submit a link to the assignment. The midterm is due one hour before class and
builds must be bug free. Everyone in the group must submit the work to Brightspace in order to
receive credit. The app needs to build to your phone without issues.
Research Project - Frameworks and APIs (partners)
Working in teams of two, create a short presentation and demo of a special framework or API.
Research one of Apple’s frameworks for swift development (AKA “kits”) or another API that you

Final Project - Published App (partners)
The Final is a fully flushed out large scale project with an emphasis on the balance between
user experience and innovative app design. Working in teams of 2 (or 3), create a professional
quality mobile app that fits an underserved market niche. Refine the app through playtesting and
iteration and release the completed version on the app store. Music, sound effects, a clean UI,
juicy feedback, and other polish elements are required. The final project may be an extension of
a previous assignment or exercise. Milestones and a groups ability to self-organize will be
critical. Betas will be presented and playtested. The final project should be submitted to the
Apple app store by Week 14 if not sooner. The final submission will also include a presentation
and documentation.
Final Pitch and Demo
Every team will pitch their concept for the final project to the class. Presentations should be
about 5 minutes each. The presentations should include a slide deck and a very basic prof of
concept that demonstrates some element of functionality.
Submit the slide deck

Final Beta
This is an 80-90% complete version of your final. The project is an MVP that is just missing its
final bit of polish. The beta needs to be as close to completion as possible in order to iron out
the final issues, as well as receive useful user feedback. Betas will be demoed and user tested

authorized by the instructor or identified in the assignment instructions. Students should review
